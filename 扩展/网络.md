# 网络

```code
  设备层 → 标识层 → 寻址层 → 转发层 → 传输层 → 应用层
  对应现实：
  网卡  →  MAC  →   IP  →  路由 → TCP/UDP → HTTP/DNS
```

- 网络本质就三件事
  1. 找到人（IP / DNS）
  2. 找到路（路由 / 网关）
  3. 把数据送过去（MAC / TCP）

1. IP、子网掩码、默认网关、DNS、MAC、端口
   - IP: 告诉别人：我是谁？`192.168.1.100`（👉 用来在网络中唯一标识一台设备）;
   - 端口: 告诉自己：数据应该交给哪个程序？`80 -> HTTP`；
   - 子网掩码: 告诉自己："谁和我是一个局域网？" `255.255.255.0`;
   - 默认网关: 告诉自己：其他网络的数据应该交给谁？`192.168.1.1`;
   - DNS: 告诉自己：域名怎么转换成 IP？`www.baidu.com -> IP`;
   - MAC ≈ 网卡的硬件身份证（物理地址）；

2. 光猫(光网络终端)：把运营商的光纤网络接进你家;
   - 负责把“光信号”转换为“网线信号”（光信号 -> 光猫 -> 网线信号）；
   - 光猫主要解决“光纤怎么接入家庭网络”的问题。
   - 调制解调器（Modem / 光猫）

3. 网卡（NIC，Network Interface Card）：就是设备连接网络的“接口”。
   - 1、Wi-Fi网卡；2、有线网卡；
   - 每个网卡都有：
     - IP地址（逻辑）
     - MAC地址（物理）

4. 网关（Gateway）：可以理解成“一个网络通往另一个网络的'出口'”。
   - 为什么需要网关？同一个局域网里的机器，可以直接通信；不同网络之间通信，就需要经过网关。
   - 默认网关：`192.168.1.1`

5. 网卡、网关： 网卡负责“出去”； 网关负责“去哪里”，往外走的下一站。

6. 路由器（路由）：把不同网络连接起来，并决定数据往哪走
   - 根据 IP 地址决定转发路径

7. 你的路由器 WAN 口可能有：
   - PPPoE：运营商给：账号 + 密码 路由器拨号。（替换以前的电话线拨号上网）
   - DHCP：运营商直接告诉路由器：
     - 你的IP：xxx.xxx.xxx.xxx
     - 网关：xxx.xxx.xxx.xxx
     - DNS：xxx.xxx.xxx.xxx

     `路由器自动获取，不需要账号密码`。

   - 静态IP：运营商直接给你：
     - IP
     - 子网掩码
     - 网关
     - DNS

     你手动配置，企业专线比较常见。

8. 交换机（Switch）：把同一个局域网里的设备连接起来
   - 根据 ”MAC 地址“ 进行 局域网内的数据转发。
   - 不看 IP，只看 MAC。

9. 路由器（路由）vs 交换机：

   ```bash
      交换机：
      PC ──┐
           ├── Switch ── NAS
      手机 ─┘

      “大家在一个小区里互相找人”


      路由器：
      家庭网络 ── Router ── Internet

      “我要去另一个小区”
   ```

10. AP(Access Point，无线接入点): 负责把 “有线网络” 变成 “无线网络”。
    - AP 做的是：有线网络 <--> 无线 Wi-Fi；
    - AP 是 Wi-Fi 和有线局域网之间的“桥”;

11. NAT(Network Address Translation，网络地址转换):
    - 它会把：`192.168.1.100:50000` 转换成类似：`公网IP:某个端口`
    - NAT 发生在“私有网络 ↔ 需要共享/转换地址的边界”，而不是“每经过一个路由器就 NAT 一次”。
    - NAT 负责“地址转换”，路由负责“找路”。

    ```bash
                 Internet
                    │
              ┌─────┴─────┐
              │   服务器   │
              └─────▲─────┘
                    │
                  普通路由
                    │
                 普通路由
                    │
                 ISP骨干网
                    │
                 普通路由
                    │
                  CGNAT     ← 有些运营商这里做 NAT
                    │
                运营商网络
                    │
                家庭路由器    ← 这里通常做 NAT
                    │
               192.168.1.100
                    │
                   电脑
    ```

12. 交换机 vs 普通路由器 vs NAT
    - 交换机 → 看 MAC
    - 普通路由器 → 看 IP，决定下一跳
    - NAT → 改 IP/端口，并建立映射

13. 防火墙(Firewall)主要负责：哪些网络连接允许通过，哪些禁止。

### 网络划分（范围）

1. 子网掩码（Subnet Mask）: 判断是不是“同一个局域网”

   ```code
   IP:       192.168.1.10
   子网掩码:  255.255.255.0

   👉 表示：
      前 3 段（192.168.1）是“网络号”
      最后一段是“主机号”

   👉同一网段：192.168.1.xxx  → 局域网
   ```

2. 网关（Gateway）: 出局域网的“门”
   - 电脑的“网口”
   - 每个网卡都有一个：IP地址、MAC地址（物理地址）

     但凡接入互联网的主机必须有一块网卡，每块网卡在出厂时都烧制好一个全世界独一无二的地址（mac地址）；

   - IP决定“去哪”
   - MAC决定“怎么送到下一跳”

3. 广播地址: “通知所有人”的地址

   👉 作用：
   - ARP广播（找别人MAC地址）
   - 局域网发现设备

4. 广播域: 广播能到达的范围
   - 广播域 = 二层（MAC层）范围

   特点：
   - 局域网内是一个广播域
   - 路由器会隔离广播

### 核心协议（规则）

1. ARP（Address Resolution Protocol）: IP → MAC 转换
   - 问：谁是 192.168.1.1？
   - 答：我是，我的MAC是XX

2. IP协议: 负责“把数据送到目标IP”
   - 不保证可靠
   - 只负责“尽力送”

3. ICMP: 网络“诊断工具”
   - ping 就是它

4. TCP: 可靠传输（打电话）

   特点：
   - 三次握手
   - 有确认机制
   - 不丢数据

5. UDP: 不可靠但快（发短信）
   - 不保证到达
   - 适合视频/游戏

### 路由与转发（核心）

1. 路由表: 决定“下一跳去哪”
2. 默认路由: 不认识的都走这里
   - 0.0.0.0/0

3. NAT: 私网IP → 公网IP
   - 家庭上网必备

4. BGP: 互联网“导航系统”
   - ISP 各大网络交换路由信息

### 一个请求的完整路径（把所有概念串起来）

👉 访问 google.com 时：

1. DNS → 获取IP
2. 判断是否同网段
3. ARP → 找网关MAC
4. 发给网关
5. 路由器查路由表
6. NAT转换公网IP
7. 经过互联网（BGP）
8. 到达服务器
9. TCP建立连接
10. HTTP请求数据

### 最核心的5个理解

1. IP vs MAC
   - IP：决定去哪
   - MAC：决定下一跳怎么送

2. 局域网 vs 互联网
   - 局域网：ARP + MAC通信
   - 外网：靠路由器

3. 默认网关: 不认识的都交给它
4. 路由本质: 每一跳只知道“下一步”
5. 分层思想（最重要）
   - 应用层：你要干嘛（HTTP）
   - 传输层：怎么传（TCP）
   - 网络层：往哪走（IP）
   - 链路层：怎么发（MAC）

### 核心对照表（重点）

| 你的模型 | OSI模型               | TCP/IP模型 | 核心作用   | 举例       |
| :------- | :-------------------- | :--------- | :--------- | :--------- |
| 应用层   | 应用/表示/会话（5-7） | 应用层     | 应用协议   | HTTP/DNS   |
| 传输层   | 传输层（4）           | 传输层     | 端到端通信 | TCP/UDP    |
| 转发层   | 网络层（3）           | 网络层     | 路由决策   | 路由表     |
| 寻址层   | 网络层（3）           | 网络层     | IP定位     | IP地址     |
| 标识层   | 数据链路层（2）       | 数据链路层 | MAC寻址    | MAC地址    |
| 设备层   | 物理层（1）           | 物理层     | 传输比特   | 网线、光纤 |

- 寻址（Addressing）：解决：目标是谁？
  - IP地址
  - 子网划分
- 转发（Forwarding / Routing）：解决：怎么到？
  - 路由表
  - 下一跳
  - 网关

| OSI层  | 实际谁在做                |
| ------ | ------------------------- |
| 应用层 | HTTP / DNS                |
| 表示层 | JSON / 编码 / TLS         |
| 会话层 | HTTP keep-alive / session |

### 👉 网络通信 = 这几件事叠加

- 应用：你要干嘛（HTTP）
- 传输：怎么保证到达（TCP）
- 寻址：目标是谁（IP）
- 转发：怎么走过去（路由）
- 标识：下一跳是谁（MAC）
- 设备：怎么发出去（网卡）

### 6层（设备→应用） 和 OSI七层、TCP/IP五层 对比

👉 OSI 是“教学分层”
👉 TCP/IP 是“实现分层”
👉 你这套是“思考分层（工程视角）”

## 🟢 场景1：访问“局域网内”设备

例子

```code
你：192.168.1.10
目标：192.168.1.20
```

- step：① 判断是不是同一网段

  用子网掩码计算：

  ```code
  192.168.1.10 → 192.168.1
  192.168.1.20 → 192.168.1
  ✔ 相同 → 局域网内
  ```

- step：② 查MAC地址（关键！）

  电脑需要知道对方的MAC地址

  👉 通过 ARP（地址解析协议）

  发送：`广播：谁是 192.168.1.20？`

  → 局域网所有设备都会收到（广播域）

  → 只有目标回应：`我是，我的MAC是 XX-XX`

- step：③ 直接通信

  之后：`IP包 → 封装成 → MAC帧`

  发送给：`目标MAC地址`

  👉 不经过网关 ❗

- ✅ 总结一句话：👉 局域网内通信 = ARP找MAC → 直接发

## 🔴 场景2：访问“局域网外”（比如百度）

例子

```code
你：192.168.1.10
目标：8.8.8.8（公网）
```

- step: ① 判断网段

  ```code
  192.168.1.xxx ≠ 8.8.8.8
  ❌ 不在同一局域网
  ```

- step: ② 发给“网关”

  电脑会这样想：👉 “我不认识这个地址，交给网关处理”

- step: ③ 找网关MAC（ARP）
  `广播：谁是 192.168.1.1？`

  网关回复：`我是，我的MAC是 YY-YY`

- step: ④ 数据发给网关

  数据结构：

  ```code
    源IP: 192.168.1.10
    目标IP: 8.8.8.8

    源MAC: 你的MAC
    目标MAC: 网关MAC  👈 注意这里！
  ```

👉 注意： 💡 IP是远端地址，但MAC是网关！

- step: ⑤ 网关开始“转发”

  网关（路由器）会：
  1. 查路由表
  2. 转发到互联网
  3. 一跳一跳走出去

- step: ⑥ NAT（关键）

  路由器会做： 👉 私网IP → 公网IP转换

  `192.168.1.10 → 你的公网IP`

- step: ⑦ 返回数据

  服务器返回 → 网关 → 再转回你

- ✅ 总结一句话：👉 跨局域网通信 = 发给网关 → 网关帮你转发
