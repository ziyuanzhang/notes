# 16. 并发编程：进程、线程、协程

## 16.1 并发与并行

- **并发（Concurrency）**：多个任务在一段时间内交替推进，宏观上同时处理多个任务。
- **并行（Parallelism）**：多个任务在同一时刻真正同时执行，通常需要多核或多执行资源。
- 并发不等于并行。

## 16.2 进程 Process

进程是操作系统进行资源分配和隔离的重要单位。每个进程通常拥有独立的虚拟地址空间。

```python
from multiprocessing import Process

def work(name):
    print("working:", name)

if __name__ == "__main__":
    p = Process(target=work, args=("task",))
    p.start()
    p.join()
```

常用操作：

- `start()`：启动子进程。
- `join()`：等待子进程结束。
- `terminate()`：请求/强制终止进程，不适合用于正常清理流程。
- `is_alive()`：检查进程是否仍在运行。
- `daemon`：守护进程设置，需在启动前配置。

进程之间默认不共享普通 Python 对象；通信需要 IPC，例如 Queue、Pipe、共享内存等。

**跨平台注意：** macOS、Windows 常见启动方式为 `spawn`；Linux 还可能使用 `fork`。多进程代码应使用 `if __name__ == "__main__":` 保护入口，避免子进程导入主模块时重复启动任务。

## 16.3 线程 Thread

线程是进程内的执行单元。同一进程中的线程共享进程地址空间，因此共享数据方便，但也需要处理竞态条件。

```python
import threading

lock = threading.Lock()
counter = 0

def work():
    global counter
    with lock:
        counter += 1

threads = [threading.Thread(target=work) for _ in range(10)]

for thread in threads:
    thread.start()

for thread in threads:
    thread.join()
```

线程适合 I/O 密集型任务，例如等待网络、磁盘、数据库响应。

## 16.4 锁与同步原语

| 原语                    | 作用                                 |
| ----------------------- | ------------------------------------ |
| `Lock`                  | 互斥锁，同一时刻只允许一个线程持有   |
| `RLock`                 | 可重入锁，同一线程可重复获取         |
| `Semaphore`             | 信号量，限制同时访问某资源的任务数量 |
| `Event`                 | 事件标志，用于通知等待方             |
| `Condition`             | 条件变量，等待某个共享状态满足       |
| `queue.Queue`           | 线程安全队列                         |
| `multiprocessing.Queue` | 进程间队列                           |

锁应使用上下文管理器：

```python
with lock:
    # 临界区
    ...
```

死锁常见原因：多个锁获取顺序不一致、持锁等待另一个任务、异常路径没有正确释放锁等。降低风险的方法：统一锁顺序、缩小临界区、避免持锁执行慢 I/O、设置合理超时。

## 16.5 GIL（全局解释器锁）

在传统 GIL 构建的 CPython 中，同一进程内通常同一时刻只有一个线程执行 Python 字节码。因此：

- 多线程适合 I/O 密集型任务。
- CPU 密集型纯 Python 计算通常难以通过多线程实现多核并行，可考虑多进程或原生扩展。
- GIL 不等于业务锁，不能代替 `Lock` 保护共享业务状态。
- 其他 Python 实现或 CPython 的特殊构建可能有不同情况；现代 CPython 也出现了可选 free-threaded 构建，不能把“Python 永远只有 GIL”当作语言定律。

## 16.6 线程池与进程池

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

def work(value):
    return value * 2

with ThreadPoolExecutor(max_workers=5) as pool:
    results = list(pool.map(work, range(10)))
```

- `ThreadPoolExecutor`：线程池，适合大量 I/O 等待任务。
- `ProcessPoolExecutor`：进程池，适合 CPU 密集型任务。
- `submit()` 返回 `Future`，可通过 `result()` 获取结果；`map()` 适合批量映射。

## 16.7 协程 Coroutine

协程是一种可以暂停并在之后恢复执行的任务。`async def` 定义的函数调用后会产生协程对象；协程需要由事件循环等机制调度运行。

```python
import asyncio

async def work():
    await asyncio.sleep(1)
    return "done"
```

协程通常在单线程事件循环中协作式切换；它不等于线程，也不会自动让 CPU 密集计算并行。

# 17. asyncio 异步编程

## 17.1 生态关系

```text
asyncio（Python 标准库异步基础设施）
        ↑
AnyIO（兼容 asyncio / Trio 等异步后端的抽象层）
        ↑
Starlette / FastAPI 等框架可通过 AnyIO 等机制管理异步任务
```

不能简单说 FastAPI、Starlette、HTTPX 的所有异步底层都“完全依赖 AnyIO”；不同库、版本和执行路径的实现有所区别。AnyIO 的价值是提供统一的异步并发抽象。

## 17.2 最小可用模板

```python
import asyncio

async def main():
    print("开始")
    await asyncio.sleep(1)
    print("结束")

asyncio.run(main())
```

- `async def` 定义协程函数。
- 调用协程函数会得到 coroutine 对象。
- `await` 用于等待可等待对象，并在等待期间让出控制权。
- `asyncio.run()` 通常用于程序入口，创建并运行事件循环。

## 17.3 顺序等待与并发等待

顺序执行：

```python
a = await fetch_a()
b = await fetch_b()
```

并发执行：

```python
results = await asyncio.gather(
    fetch_a(),
    fetch_b(),
)
```

`gather()` 的结果顺序与传入 awaitable 的顺序一致，而不是谁先完成就排在谁前面。

## 17.4 Task 与 TaskGroup

```python
task = asyncio.create_task(fetch_data())
result = await task
```

创建 Task 后，事件循环可以调度该任务。应保存需要管理的 Task 引用，并妥善处理异常与取消。

Python 3.11+ 推荐了解结构化并发 `TaskGroup`：

```python
async def main():
    async with asyncio.TaskGroup() as group:
        group.create_task(fetch_a())
        group.create_task(fetch_b())
    # 离开上下文时，组内任务已完成或按规则取消
```

TaskGroup 中任务失败时，会触发组级别的取消与异常传播，具体异常可能以 `ExceptionGroup` 形式呈现。

## 17.5 异步代码中的阻塞陷阱

错误：

```python
async def bad():
    time.sleep(1)          # 阻塞事件循环线程
    requests.get(url)      # 同步 HTTP 请求也会阻塞
```

推荐：

```python
async def good():
    await asyncio.sleep(1)
    response = await async_client.get(url)
```

如果暂时只能使用同步阻塞 I/O 函数：

```python
result = await asyncio.to_thread(blocking_function, arg)
```

`asyncio.to_thread()` 主要用于把阻塞 I/O 函数放到线程中执行，不是让纯 Python CPU 密集计算自动获得多核并行。

## 17.6 asyncio 的适用边界

适合：

- 大量网络请求。
- 高并发 I/O 等待。
- 异步数据库、异步 HTTP 客户端。
- WebSocket、长连接等。

不适合直接解决：

- 纯 Python CPU 密集计算。
- 本身没有异步接口且无法隔离的阻塞调用。
- 需要多核并行计算的任务。

异步不是“执行速度一定更快”，而是提高等待期间的资源利用率和并发承载能力。

# 18. I/O 模型与高性能网络基础

## 18.1 一次 I/O 的两个阶段

以网络接收为例：

1. **等待数据准备好**：数据从网络到达，并进入内核 socket 接收缓冲区。
2. **数据拷贝**：数据从内核缓冲区复制到用户空间缓冲区，供应用程序使用。

很多网络 I/O 的主要等待发生在第一阶段。

## 18.2 五种经典 I/O 模型

| 模型         | 核心行为                           | 应用程序是否还要 `recv/read`               |
| ------------ | ---------------------------------- | ------------------------------------------ |
| 阻塞 I/O     | 调用等待数据就绪，之后等待拷贝完成 | 是                                         |
| 非阻塞 I/O   | 数据未就绪时立即返回，应用反复尝试 | 是                                         |
| I/O 多路复用 | 内核监视多个 fd，通知哪些 fd 就绪  | 是                                         |
| 信号驱动 I/O | 数据就绪时通过信号通知应用         | 通常是                                     |
| 异步 I/O     | 应用提交请求，内核完成 I/O 后通知  | 典型完成模型中不需要再主动执行同一读取操作 |

这里的“异步 I/O”是经典 I/O 模型语境下的概念，不要与 Python `async def` 直接画等号。

## 18.3 select、poll、epoll

- `select`：使用集合描述要监视的 fd，存在平台相关的数量限制；每次调用通常需要重新传入并扫描集合。
- `poll`：使用 pollfd 数组，缓解了传统 `select` 的 fd 数量限制，但仍需要遍历检查就绪项。
- `epoll`：Linux 提供的 I/O 事件通知机制，适合大量连接场景；通过内核维护关注集合和就绪事件，减少无效扫描。

`epoll` 通知的是**就绪（ready）**：某个 fd 现在可以尝试读/写；应用仍需调用 `recv()` / `send()` 完成相应操作。它通常归入同步 I/O 多路复用，而不是内核替应用完成全部数据拷贝的异步 I/O。

## 18.4 同步/异步与阻塞/非阻塞是两个维度

- **阻塞/非阻塞**：描述调用是否会让当前线程等待。
- **同步/异步**：描述 I/O 操作由谁推进、何时以何种方式通知完成。

典型理解：

- epoll：等待事件时，线程可能阻塞在 `epoll_wait()`；收到 ready 后，应用主动 `recv()`，属于 I/O 多路复用/同步 I/O。
- 典型异步 I/O：应用提交请求，内核完成操作后通知 completion。

因此“非阻塞 I/O 就是异步 I/O”是错误的。

## 18.5 Reactor 与 Proactor

- **Reactor**：关注事件就绪；事件发生后由应用执行读写处理。常与 `select`、`poll`、`epoll` 组合。
- **Proactor**：应用先提交异步 I/O 请求，由系统完成操作，再通知应用结果。

## 18.6 asyncio 与事件循环

可以用下面的概念链理解常见 asyncio 网络 I/O：

```text
协程任务
   ↓
await 等待网络 I/O
   ↓
事件循环把 socket 注册到 I/O 多路复用机制
   ↓
内核监视 socket 是否就绪
   ↓
就绪事件通知事件循环
   ↓
事件循环恢复对应协程
   ↓
协程继续执行后续读写逻辑
```

不同操作系统底层可能使用 epoll、kqueue、IOCP 等不同机制。不要把 asyncio 永远等同于 Linux epoll。

## 18.7 用户态、内核态、DMA 与零拷贝

- 用户态程序通过系统调用请求内核执行文件、网络等操作。
- 用户态/内核态切换有成本，但不是每次切换都等价于一次完整的线程上下文切换。
- DMA 允许设备在 DMA 控制器协助下与内存传输数据，减少 CPU 逐字节搬运。
- 零拷贝是一类减少数据复制和用户态参与的技术，不代表所有路径完全没有数据复制。

传统文件发送网络的概念路径：

```text
磁盘/页缓存
   ↓
用户空间缓冲区
   ↓
内核 socket 缓冲区
   ↓
网卡
```

使用 `sendfile()` 等机制时，可以在适用条件下减少数据经过用户空间的往返拷贝。实际内核、驱动、协议和硬件路径会更复杂，不能把示意图当成所有机器的固定执行细节。

## 18.8 高并发的核心思路

高并发不只是“开更多线程”，还包括：

1. 不让线程长时间空等 I/O。
2. 减少不必要的线程/任务切换。
3. 控制数据复制与内存分配。
4. 减少不必要的系统调用。
5. 做好连接、队列、线程池和任务数量的背压管理。

常见技术关联：

| 技术     | 相关思想                                   |
| -------- | ------------------------------------------ |
| Redis    | 事件驱动网络处理；具体版本与线程模型有演进 |
| Nginx    | 事件驱动、多路复用、`sendfile` 等          |
| asyncio  | 事件循环、协程、平台 I/O 事件机制          |
| Netty    | Reactor 等网络事件驱动模型                 |
| Kafka    | 页缓存、批量 I/O、零拷贝相关优化           |
| io_uring | Linux 新一代异步 I/O 接口                  |
| IOCP     | Windows 完成端口机制                       |

# 19. 核心概念对照表

| 概念         | 关键点                           |
| ------------ | -------------------------------- |
| 可迭代对象   | 能通过 `iter()` 获取迭代器       |
| 迭代器       | 能通过 `next()` 逐个产出值       |
| 生成器       | 用生成器函数或表达式创建的迭代器 |

## 19.3 进程、线程、协程

| 维度     | 进程             | 线程             | 协程                   |
| -------- | ---------------- | ---------------- | ---------------------- |
| 所属层级 | 操作系统         | 操作系统         | 语言/运行时任务        |
| 内存     | 通常独立地址空间 | 同进程内共享     | 通常运行在某个线程上   |

## 19.4 并发方案选择

| 场景                               | 优先考虑                          |
| ---------------------------------- | --------------------------------- |
| 大量同步 I/O 调用，改造成本低      | 线程池                            |
| 大量异步网络 I/O                   | asyncio / 异步客户端              |
| 纯 Python CPU 密集计算             | 多进程                            |
| NumPy 等释放 GIL 的原生计算        | 结合库特性评估线程/进程           |
| 简单后台任务                       | 线程/任务队列，视生命周期要求选择 |
| 需要可靠任务投递、重试、跨机器执行 | 专门的任务队列/工作进程架构       |

## 19.5 内置函数与对象协议速查

| 目标       | 常用入口                          | 相关协议/注意点                       |
| ---------- | --------------------------------- | ------------------------------------- |
| 看类型     | `type()`、`isinstance()`          | 类型判断不等于身份判断                |
| 看身份     | `id()`、`is`                      | 不用于比较普通值                      |
| 看属性     | `dir()`、`getattr()`、`hasattr()` | 动态属性访问属于反射                  |
| 看长度     | `len()`                           | `__len__()`                           |
| 遍历对象   | `iter()`、`next()`、`enumerate()` | 迭代协议                              |
| 组合数据   | `zip()`                           | 默认按最短输入停止                    |
| 映射/过滤  | `map()`、`filter()`               | 返回迭代器                            |
| 排序       | `sorted()`                        | 返回新列表；依赖 key 或元素间可比较性 |
| 反向遍历   | `reversed()`                      | 返回反向迭代器，不是原地修改          |
| 真值判断   | `bool()`、`all()`、`any()`        | `__bool__()` / `__len__()`            |
| 字符串表示 | `str()`、`repr()`、`format()`     | 面向用户/开发者/格式规范              |
| 动态执行   | `eval()`、`exec()`                | 不可信输入存在代码执行风险            |

## 19.6 相等、身份与共享状态速查

| 情况                      | 是否共享同一对象             | 应如何理解                             |
| ------------------------- | ---------------------------- | -------------------------------------- |
| `b = a`                   | 是                           | 赋值建立新名字绑定，不复制对象         |
| `b = a.copy()`            | 否（外层容器不同）           | 浅拷贝，内部成员可能仍共享             |
| 小整数/字符串字面量       | 有时可能                     | 解释器优化，不依赖 `is`                |
| `None` / `True` / `False` | 是对应单例                   | 可用 `is` 判断                         |
| 可变默认参数              | 多次调用共享默认对象         | 默认值在定义函数时求值                 |
| 可变类属性                | 多实例可能访问同一对象       | 类属性由类对象持有                     |
| 闭包变量                  | 闭包函数共享被捕获的变量绑定 | 需要固定循环值时可用默认参数或工厂函数 |

# 20. 原笔记关键错误与修正清单

以下是原始笔记中容易造成错误理解的点，统一修正如下：

1. **“Python 是解释型语言”**：作为入门分类可以使用，但更准确地说，CPython 会先编译为字节码，再由虚拟机执行。
2. **“垃圾回收回收没有变量名的值”**：不准确。对象可能被容器、闭包、栈帧等引用；CPython 主要依靠引用计数并配合循环垃圾回收。
3. **“id 就是内存地址”**：语言规范只保证对象存活期间身份标识唯一且稳定；CPython 中通常与地址相关。
4. **“字符串比较转 ASCII / 汉字转 UTF-8 或 GBK 比较”**：Python 3 的 `str` 按 Unicode 码点进行字典序比较。
5. **“集合只能存不可变类型”**：准确说是集合元素必须可哈希；常见不可变对象通常可哈希，但自定义类型可自行实现哈希规则。
6. **“字典无序”**：Python 3.7+ 保证字典按插入顺序迭代。
7. **“字典 key 不可以是数据容器”**：不准确。可哈希的元组可以作为 key；列表、字典、集合等不可哈希对象不能直接作为 key。
8. **“元组里面的值都不能变”**：元组外层结构不可变，但其中的可变对象仍可修改。
9. **“位置参数必须写前面、默认参数放最后”**：这是常见函数签名的简化说法；还要考虑 `*args`、仅限关键字参数和 `**kwargs` 的语法规则。
10. **“默认参数每次调用都会重新创建”**：错误。默认参数表达式在函数定义时求值一次，使用可变默认值容易产生状态共享问题。
11. **“`__del__` 在文件执行结束或删除对象时必然立即调用”**：不可靠。对象终结时机受引用关系和实现影响，不能用它承担关键资源清理。
12. **“多继承优先左边父类”**：不完整。属性查找按 MRO（C3 线性化）执行，使用 `Class.mro()` 查看；`super()` 按 MRO 继续查找。
13. **“双下划线属性是真正私有属性”**：错误。它主要触发名称改写，不是访问控制或安全机制。
14. **“两个锁就锁不住”**：错误。多个锁可以正确使用；但需要统一加锁顺序，避免死锁。锁保护的是共享临界区，不是锁对象的数量。
15. **“GIL 意味着 Python 只能通过多进程并行”**：仅适用于传统 GIL 构建的 CPython 纯 Python 字节码执行场景。原生扩展可能释放 GIL，且已有可选 free-threaded CPython 构建。
16. **“守护进程/线程就是主程序结束时所有任务都安全结束”**：守护任务可能被直接终止，清理代码不一定完整执行；重要任务应显式等待、取消并回收。
17. **“`asyncio.create_task()` 创建的任务不保存引用就一定会被垃圾回收”**：更准确地说，事件循环对任务的强引用保证并非所有场景都能替代应用自己的生命周期管理；应保存任务引用并处理异常/取消。
18. **“`asyncio`、AnyIO、FastAPI 是固定的单向依赖链”**：不应绝对化。AnyIO 提供异步抽象，具体库和版本的内部调用路径不同。
19. **“`await` 只能在 async 函数里使用”**：普通 `.py` 模块中通常如此；交互式环境、特定框架或支持顶层 await 的环境有额外规则。
20. **“`asyncio` 能让 CPU 密集计算自动并行”**：错误。协程主要用于协作式 I/O 并发；CPU 密集任务应考虑进程池或原生计算库。
21. **“epoll 是异步 I/O”**：经典模型分类中，epoll 属于 I/O 多路复用，通知的是就绪事件；应用仍需调用 `recv()` / `send()`。
22. **“非阻塞 I/O 等于异步 I/O”**：错误。阻塞/非阻塞与同步/异步是两个不同维度。
23. **“零拷贝就是完全没有拷贝”**：不准确。通常指减少数据复制、用户态参与或系统调用，实际路径取决于操作系统和硬件。
24. **文件读取的字符/字节单位**：文本模式 `read(n)` 的 n 通常是字符数；二进制模式是字节数。不要把两者混淆。
25. **`writelines()` 不自动添加换行符**：需要在每个字符串中自行包含 `\n`。
26. **`flush()` 不等于绝对持久化到物理介质**：它刷新 Python 层缓冲；更强的持久化语义还涉及操作系统与存储设备。

27. **“小整数缓存范围是 Python 语言规范”**：错误。`-5` 到 `256` 是 CPython 常见实现细节，不是跨解释器保证。
28. **“所有相同字符串都会驻留”**：错误。字符串驻留策略与解释器实现、上下文有关；需要时可显式使用 `sys.intern()`，但不要用它替代正确的数据建模。
29. **“相同字面量 `is` 为 True 就说明可以用 `is` 比较字符串”**：错误。应使用 `==` 比较值，`is` 比较身份。
30. **“`None`、`True`、`False` 与小整数缓存性质相同”**：不准确。前几者是语言内建单例；小整数缓存是实现优化。
31. **“空元组/空 `frozenset` 一定是单例”**：不能作为通用语言保证；尤其不要依赖容器构造的身份结果。
32. **“`1 + 2` 常量折叠成 `6`”**：明显笔误，正确结果是 `3`。常量折叠只改变计算发生的时机，不改变表达式结果。
33. **“`sorted(obj)` 直接调用 `obj.__lt__()` 一次”**：过度简化。排序通过比较协议进行比较，也可通过 `key=` 提供排序键；比较分派可能涉及多个特殊方法。
34. **“`reversed(obj)` 一定调用 `__reversed__()`”**：不准确。优先使用 `__reversed__()`，否则可使用序列协议（`__len__` 和整数索引 `__getitem__`）。
35. **“`isinstance()` 会调用对象类自身的 `__instancecheck__()`”**：不准确。相关钩子属于目标类元类层面的机制，且抽象基类等也有专门规则。
36. **“所有内置函数都直接对应一个同名魔法方法”**：错误。协议入口、回退规则和分派过程各不相同；对照表只是常见对应关系。
37. **“`__import__()` 是推荐的动态导入方式”**：不推荐。通常使用 `importlib.import_module()`。
38. **“`locals()` 返回字典，修改它就能可靠修改函数局部变量”**：不可靠。不要依赖修改 `locals()` 的结果来改变优化过的函数局部变量。

# 21. 建议学习顺序

建议按依赖关系学习，而不是按“基础、进阶、高级”文件名机械推进。

## 第一阶段：语言基础

1. 变量名与对象、`id/type/value`、可变与不可变。
2. 数值、字符串、列表、元组、字典、集合。
3. 索引、切片、运算符、条件与循环。
4. 函数、参数、返回值、解包。
5. 异常处理与文件读写。

**阶段目标：** 能独立编写小型脚本，读写数据并组织函数。

## 第二阶段：程序组织与面向对象

1. 模块、包、导入机制、`__name__`。
2. 命名空间、作用域、LEGB、`global`、`nonlocal`。
3. 类、实例、属性、方法、继承、组合、多态。
4. `property`、魔法方法、反射。
5. 赋值、浅拷贝、深拷贝。

**阶段目标：** 能把脚本整理成结构清晰、可维护的多模块项目。

## 第三阶段：Python 语言进阶能力

1. 迭代协议、可迭代对象、迭代器。
2. 生成器、推导式。
3. 闭包与装饰器。
4. 常用标准库：`pathlib`、`json`、`logging`、`datetime`、`subprocess` 等。
5. 项目依赖、虚拟环境、`pyproject.toml`、`uv`。

**阶段目标：** 能读懂常见 Python 库的接口设计，掌握常见工程化工具。

## 第四阶段：并发与网络

1. TCP/UDP、socket、HTTP 基础。
2. 进程、线程、锁、队列。
3. 线程池、进程池、Future。
4. 协程、事件循环、`async` / `await`。
5. `asyncio`、`Task`、`TaskGroup`、取消与异常处理。
6. I/O 多路复用、Reactor、Proactor、零拷贝概念。

**阶段目标：** 能根据任务类型选择同步、线程池、进程池或异步 I/O。

## 第五阶段：面向 Python 后端与 AI 应用开发

在语言基础稳定后，再进入：

1. FastAPI：路由、请求/响应、依赖注入、Pydantic。
2. 数据库：SQL、PostgreSQL、SQLAlchemy 2.x、Alembic。
3. 认证授权：JWT、RBAC、权限边界。
4. 异步后端：async endpoint、异步数据库驱动、HTTPX。
5. 工程化：日志、配置、测试、类型检查、Lint、CI/CD。
6. AI 应用：模型 API、工具调用、RAG、Agent、任务编排与可观测性。
