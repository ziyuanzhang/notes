# 初始化与默认值

```bash
   客户端请求
       │
       │ 没传字段？
       ↓
   ┌──────────────────────┐
   │  Pydantic Model      │  ← API 层默认值
   │  Field(default=...)  │
   └──────────┬───────────┘
              │
              ↓
   ┌──────────────────────┐
   │  Python / Service    │  ← 业务层初始化
   │  if xxx is None ...  │
   └──────────┬───────────┘
              │
              ↓
   ┌──────────────────────┐
   │  SQLAlchemy Model    │  ← ORM 层默认值
   │  default=...         │
   └──────────┬───────────┘
              │
              ↓
   ┌──────────────────────┐
   │  PostgreSQL          │  ← 数据库默认值
   │  DEFAULT ...         │
   └──────────────────────┘
```

- 初始化解决“对象刚创建时是什么”；
- 默认值解决“调用方没提供值时是什么”；
- nullable 解决“数据库最终允不允许 NULL”；
- 而 Pydantic、SQLAlchemy、数据库分别负责不同层级的默认值。

## default 问题

1. Pydantic之：一个非常重要的坑: default ≠ nullable
2. Pydantic之：default 和 default_factory
   - default = 固定默认值
   - default_factory = 每次创建对象时重新生成一个值

3. SQLAlchemy之: default
   - default=datetime.now --> 函数
   - default=datetime.now() --> 现在就执行❌

4. SQLAlchemy之: default 和 server_default
   - default: SQLAlchemy / Python 负责默认值
   - server_default: 数据库负责默认值

## 🔥 最重要的区别

```bash
  # ① 对象有没有创建？
  user is None

  # ② 有没有这个属性？
  hasattr(user, "username")

  # ③ 属性有没有值？
  user.username is None
```

## None 问题

| 层级       | 空值表示 |
| :--------- | :------- |
| Python     | None     |
| Pydantic   | None     |
| SQLAlchemy | None     |
| PostgreSQL | NULL     |

❗Python 用 None，SQL 数据库用 NULL，ORM 负责两者之间的转换。
❗Pydantic 的 | None 管“接口允许不允许空”，SQLAlchemy 的 nullable 管“数据库允许不允许 NULL”。
